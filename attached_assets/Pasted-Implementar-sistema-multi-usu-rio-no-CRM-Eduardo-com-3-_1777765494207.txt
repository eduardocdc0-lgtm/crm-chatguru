IMPLEMENTAÇÃO TÉCNICA:

1) Criar tabela users:
   - id (serial, PK)
   - username (text, unique, not null)
   - password_hash (text, not null) - usar bcrypt ou argon2
   - role (text, not null) - "admin" ou "agent"
   - agent_id (integer, FK pra agents, nullable - admin não tem agent)
   - active (boolean, default true)
   - created_at, updated_at

2) Seed inicial:
   - 1 user admin (Eduardo) com senha hashada
   - 1 user agent (Thiago) com agent_id apontando pro registro do Thiago em agents
   - 1 user agent (Tammyres) com agent_id apontando pro registro da Tammyres em agents
   
3) Endpoint POST /api/login → recebe {username, password}, retorna sessão com role e agent_id

4) Middleware requireAuth — verifica sessão antes de qualquer rota
5) Middleware filterByAgent — se role = "agent", aplica WHERE assigned_agent = sessao.agent_id em todas queries
6) Middleware requireAdmin — bloqueia rotas que só admin pode usar

7) Frontend: 
   - Tela de login antes de qualquer outra coisa
   - Após login, esconder itens de menu conforme role
   - Botão de logout no rodapé do menu lateral
